# game-model — G2 모델 게이트

코드도 아트도 없이 **핵심 루프가 수학적으로 성립하는지**를 며칠 안에 판정한다.
UNFOUND에서 이 단계가 "턴당 조합 0.3회 — 게임 불성립"을 하루 만에 잡아냈다. 그게 이 게이트의 존재 이유다.

## 전제

- `docs/pipeline.md`의 G2 기준과 해당 게임의 `docs/00-SSOT.md`를 먼저 읽는다
- 게임 규칙·콘텐츠·수치는 전부 `data/*.json`. 코드 하드코딩 금지
- 튜닝값은 `rules.json` 한 곳에 모으고, 변경마다 changelog에 이유를 남긴다
- SSOT에 없는 규칙이 구현 중 필요해지면 임의로 정하지 말고 `undecided`에 올린다

## 작업 순서

1. SSOT에서 **핵심 동사**(이 게임에서 플레이어가 반복하는 행동)를 확정한다. 지표는 전부 이것 기준이다
2. 데이터 스키마 설계: 콘텐츠 유형별 JSON + 효과/행동은 제한된 팔레트를 참조하는 구조로
3. `tools/validate.mjs` 작성 — 참조 무결성 + 이 게임 고유의 구조 건강도 (예: 조합 게임이면 그래프 분기도)
4. `tools/simulate.mjs` 작성 — 자동 플레이 N판, **시드 고정**, 재현 가능하게. `Date.now()`·비시드 랜덤 금지
5. 더미 콘텐츠 최소량으로 기준선 측정 → G2 지표 표 작성
6. 미달 지표는 **한 번에 값 하나씩** 바꿔 개선 시도. 시도마다 기록. 3라운드 안에 방향이 안 잡히면 game-gate 판정 요청

## 시뮬레이터 작성 원칙

- AI는 탐욕적이어도 된다. 절대값이 아니라 **변화 방향**을 재는 도구다
- 전투/코어 로직은 UI 없는 순수 함수로 — G3에서 게임 본체가 같은 로직을 쓴다
- 지표는 pipeline.md의 G2 기준 4종 + 게임 고유 위험 지표 (SSOT의 미결 질문에서 뽑는다)

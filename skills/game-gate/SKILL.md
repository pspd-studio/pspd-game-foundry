# game-gate — 판정과 부검

파운드리의 가치는 만드는 속도가 아니라 **죽이는 속도**다.
이 스킬의 산출물은 판정 하나와, 킬이면 부검 한 장이다.

## 판정 순서

1. 해당 게임의 `STATUS.md`, `docs/00-SSOT.md`, 최근 지표를 읽는다
2. `docs/pipeline.md`에서 해당 게이트의 기준을 **그대로** 가져온다
   - 판정 중 기준 수정은 금지. 기준이 틀렸다고 판단되면 "기준 수정 제안"을 별도로 올리고, 이번 판정은 현행 기준으로 한다
3. 기준 항목별로 측정값 / 목표 / 충족 여부를 표로
4. 판정:
   - **통과** — 전 항목 충족. STATUS 갱신, 다음 게이트 스킬 안내
   - **계류** — 미달이지만 개선 경로가 구체적으로 존재. 남은 시도 횟수를 명시 (G2는 3회, G3는 2회)
   - **킬** — 시도 소진, 또는 원인이 조정이 아니라 기획 구조에 있음
5. 매몰비용 논리("여기까지 왔는데")는 판정 근거에서 배제한다. 지금까지 쓴 시간은 어느 판정을 해도 돌아오지 않는다

## 킬 절차

1. `STATUS.md` → `KILLED (게이트, 날짜, 걸린 기준)`
2. `docs/90-postmortem.md` 한 장:
   - 가설: 이 게임이 재밌을 거라 믿은 이유
   - 사인: 어느 게이트, 어느 숫자에서 죽었나
   - 회수물: 다음 게임으로 가져갈 것 **정확히 3개** (데이터 구조, 도구, 교훈)
3. 폴더는 지우지 않는다. 파운드리 README의 화물 표를 갱신한다
4. 공정 결함이 보였으면 `docs/pipeline.md` 수정 제안을 함께 올린다 — 죽은 게임에서 공정이 배우는 것이 이 파운드리의 진짜 산출물이다

## 보고 형식

```
[게임명] 게이트 GN 판정

| 기준 | 측정 | 목표 | 충족 |
|---|---|---|---|

판정: 통과 / 계류(남은 시도 n회) / 킬
사유: 한 문장.

(킬이면) 회수물 3개:
1. ...

결정 요청 (최대 1개 — 판정 수용 여부)
```

최종 결정은 언제나 PSPD가 한다. 단, 판정을 뒤집을 때는 그 사유를 STATUS.md에 남긴다 —
"감으로 살렸다"도 기록되면 데이터다.

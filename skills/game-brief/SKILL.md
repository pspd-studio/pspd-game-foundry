# game-brief — G1 기획 게이트

목적은 좋은 기획서를 쓰는 것이 아니라 **나쁜 아이디어를 반나절 안에 죽이는 것**이다.
PSPD는 시간이 없다. 여기서 못 죽인 아이디어는 몇 주를 잡아먹는다.

## 전제

- 파운드리 저장소의 `docs/pipeline.md`에서 G1 기준을 먼저 읽는다
- PSPD의 제약을 항상 적용한다: 1인 개발 / 비개발자 / 아트 조달 약함 / 투입 시간 매우 적음
- 아트 물량이 재미의 원천인 기획은 아무리 매력적이어도 통과시키지 않는다

## 작업 순서

1. 아이디어를 듣고, 부족한 부분은 **최대 3개 질문**으로 채운다. 질문을 늘어놓지 않는다
2. 유사작을 웹에서 검색한다 (스팀 태그, 출시일, 평가, 가격). 차별점은 유사작을 알아야 쓸 수 있다
3. 한 장 기획서를 작성한다:
   - **한 줄 정의** (장르 + 핵심 동사 + 차별점이 한 문장에)
   - **핵심 감정** — 플레이어 입에서 나와야 할 문장 3~4개
   - **핵심 루프** — 화살표 다이어그램
   - **차별점 한 줄** — "유사작 X와 달리 이 게임은 ___"
   - **수익 가설** — 플랫폼 / 가격대 / 누가 왜 사는가
   - **1인 제작 적합성** — 고품질 아트가 필요한 오브젝트 수 추정, 콘텐츠 제작량 추정
   - **핵심 검증 질문** — G2·G3에서 확인할 것들 (숫자로 적을 수 있는 형태로)
4. G1 즉시 킬 4항목을 하나씩 판정하고 근거를 한 줄씩 적는다
5. 통과면: 저장소 `template/`을 `games/<게임id>/`로 복제하고 기획서를 `docs/00-SSOT.md`에 반영, `STATUS.md`를 `G1-PASSED`로
6. 킬이면: 기획서와 킬 사유만 남긴다. 폴더를 만들지 않는다

## 판정 원칙

- 애매하면 통과시키지 않는다. G1 통과의 의미는 "재밌다"가 아니라 "거짓말이 없다"다
- 킬 판정에 PSPD가 반발하면 근거로 설득하되, 최종 결정은 PSPD가 한다. 단 "기준을 판정 중에 바꾸는 것"만은 막는다

## 보고 형식

```
[게임명] G1 판정: 통과 / 킬

한 줄 정의: ...
킬 검사: 감정✓ 아트의존✓ 차별점✓ 제작량✓  (걸린 항목은 사유 한 줄)

결정 요청 (최대 3개)
1. ...
```

기획서 전문은 파일로 저장하고 채팅에는 붙이지 않는다.

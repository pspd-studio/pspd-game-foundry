# game-slice — G3 슬라이스 게이트

시뮬레이터는 AI가 논 것이다. G3는 **사람이 재밌어하는지**를 잰다.
아트는 없다. 카드는 이름 텍스트, 오브젝트는 색 도형. 그래도 재미 검증에는 지장이 없고,
여기서 아트를 넣기 시작하는 순간 "아까워서 못 죽이는" 게임이 된다.

## 전제

- G2의 시뮬레이터와 **같은 코어 로직**(순수 함수)을 쓴다. 로직을 두 번 짜지 않는다
- 스택: TypeScript + Vite, 렌더링 DOM/CSS 우선, 상태 라이브러리 금지
- 배포: Vercel. 커밋 → 플레이 링크 자동 갱신. 테스터에게는 링크만 던진다
- 콘텐츠·수치는 여전히 `data/*.json`에서만 읽는다

## 작업 순서

1. 코어 로직을 게임 패키지로 분리 (시뮬레이터와 공유)
2. 최소 UI: 핵심 동사가 60초 안에 일어날 수 있는 화면. 튜토리얼은 문장 3개 이하
3. 플레이 로그 수집 (Supabase, 익명):
   - 핵심 동사의 시도·성공 기록과 시점
   - **실패한 시도** (플레이어가 기대했지만 없는 것 — 다음 콘텐츠의 최고 근거)
   - 세션 길이, 판 수, 이탈 지점, 패배 지점
4. 배포 → PSPD에게 링크 보고 → 테스터 모집은 PSPD 몫
5. 표본 10명 차면 playtest 분석: pipeline.md G3 기준 4종 + 분포(평균만 보지 않는다)
6. 미달이면 개선 라운드 (최대 2회) → 그래도 미달이면 game-gate 회부

## 하지 말 것

- 아트 에셋 추가 (G3 통과 전 금지)
- 표본 10명 미만으로 결론 내기 — "표본 부족"이라 쓰고 멈춘다
- SSOT 미확정 항목을 코드에서 임의 확정 — 스위치로 두고 결정 요청
- 시뮬과 사람 지표가 어긋날 때 사람 쪽을 의심하기 — **사람이 맞다.** 시뮬레이터를 고친다

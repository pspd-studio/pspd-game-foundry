# 에셋 조달 전략 v0.2

원본 PDF에서 출처 각주가 전부 깨져 있었다(`椀爀　攀爀モ`). 아래는 링크를 복구하고
"무료 에셋으로 프로토타입"이 이 게임에 실제로 맞는지 재검토한 판이다.

---

## 대원칙

이 프로젝트의 가장 큰 위험은 프로그래밍이 아니라
**재미가 검증되기 전에 아트와 콘텐츠를 너무 많이 만드는 것**이다.

```
게임성 검증 → 시스템 안정화 → 아트 스타일 확정 → 고품질 에셋 제작
```

무료 에셋의 목표는 게임 전체를 공짜로 만드는 것이 아니라,
**검증에 돈을 쓰지 않고 검증된 뒤에만 제한적으로 쓰는 것**이다.

---

## 원본 계획에서 바꾼 것

### 프로토타입 단계에서 무료 에셋을 찾지 않는다

Kenney 같은 CC0 팩에 돌·나무·금속은 있다. 하지만 이 게임의 카드에는
**"시간", "기억", "일식"** 같은 개념 카드가 있고, 그런 아이콘은 어떤 무료 팩에도 없다.
Tier C뿐 아니라 Tier B 상당수가 기존 에셋에 존재하지 않는다.

따라서 Stage 0~1은 **카드 이름 텍스트 + 색 사각형**으로 간다.
조합 재미 검증에는 아무 지장이 없고, 에셋 탐색에 쓸 시간을 전부 아낀다.
무료 에셋 조사는 **아트 스타일이 확정된 뒤**로 미룬다.

### 통일 규칙을 코드로 강제한다

무료 에셋을 섞으면 "붙여넣은 게임"처럼 보인다. 이걸 막는 것은 에셋의 품질이 아니라 **통일된 규칙**이다.
그리고 그 규칙은 사람이 지키는 것보다 **후처리 스크립트가 강제하는 편이 확실하다.**

| 통일 대상 | 자동화 가능 |
|---|---|
| 팔레트 (색 수 제한) | 가능 — 양자화 |
| 실루엣 외곽선 굵기 | 가능 |
| 그림자 방향 | 가능 |
| 카드 프레임·비율 | 가능 |
| 배경 제거 | 가능 |
| 명암 단계 | 가능 |
| 출처·라이선스 기록 | 가능 — 파이프라인이 자동 기입 |
| 구도와 매력 | 불가능 — 사람이 고른다 |

소스가 무료 에셋이든 생성이든 직접 그린 것이든, 마지막 후처리가 같으면 한 작품처럼 보인다.
스타일이 확정되는 시점에 이 스크립트를 만든다.

## 티어별 조달

| 티어 | 예시 | 방법 |
|---|---|---|
| A 기본 재료 | 돌·나뭇가지·물·씨앗·금속 | 텍스트 → 나중에 무료 에셋 + 색 통일 |
| B 일반 발견물 | 도끼·횃불·물약·덫 | 무료 에셋 수정 또는 저가 팩 |
| C 기억에 남을 발견물 | 시간·기억·일식·보스 | 직접 제작 또는 외주. **여기에만 돈을 쓴다** |

핵심은 **카드 수만큼 아트 비용이 증가하는 구조를 피하는 것**이다.

## 돈을 쓴다면 순서

1. 핵심 발견물의 대표 아트 (발견 순간이 이 상품의 핵심 경험이다)
2. 타이틀 / 스토어 키아트
3. UI · 카드 프레임 최종 디자인
4. 보스
5. 핵심 VFX
6. 사운드 · 음악
7. 일반 카드 추가 일러스트

## 라이선스 관리

무료 에셋을 많이 쓸수록 **"어디서 받았는지 기억 못 하는 문제"** 가 출시 리스크가 된다.
`assets/registry.csv`를 프로젝트 첫날부터 유지한다. 손으로 채우면 안 채워지므로,
에셋을 받는 스크립트가 자동으로 한 줄을 추가하게 만든다.

기본값은 CC0로 잡는다. CC-BY도 쓸 수 있지만 크레딧 관리 부담이 생긴다.

- **Kenney** — 다수의 2D/3D/UI/오디오 에셋이 CC0이며 상업 사용 가능, 출처 표기 필수 아님
- **OpenGameArt** — 상업 사용 가능하지만 **작품별로 라이선스가 다르다.** CC0와 CC-BY가 섞여 있으므로 개별 확인 필수
- **itch.io** — 무료·저가 에셋이 많지만 "무료"가 곧 상업 사용 허용은 아니다. 상품별 라이선스 확인 필수

## 생성형 AI의 위치

콘셉트 탐색과 반복 변형의 보조로 쓴다. 게임 전체 스타일을 한 번에 만드는 도구로 보지 않는다.
이 게임은 카드 간 관계가 핵심이라 오브젝트의 스타일 일관성이 특히 중요하고,
그 일관성은 생성 단계가 아니라 후처리 단계에서 확보하는 편이 안정적이다.

**스팀 출시 시 유의점.** 밸브는 AI 생성 콘텐츠 공개를 요구하며, 2026년 1월 기준
**플레이어가 실제로 보는 콘텐츠**(카드 아트, 사운드)가 대상이고 개발 과정의 효율화 도구는 대상이 아니다.
즉 코드 작성에 AI를 쓰는 것은 공개 대상이 아니지만, 카드 아트를 생성으로 만들면 스토어 페이지에 표기된다.
현재 스팀 신작의 상당수가 이미 표기 중이라 불이익이라기보다 기본값에 가깝다.
출시 시점에 정책을 다시 확인할 것.

## 1인 개발에서 피해야 할 함정

1. 초반부터 카드 200장을 만들지 않는다
2. 레시피가 확정되지 않았는데 일러스트부터 만들지 않는다
3. 무료라는 이유만으로 라이선스가 불명확한 이미지를 쓰지 않는다
4. 서로 다른 스타일의 무료 에셋을 무작정 섞지 않는다
5. 생성 결과를 대량 생산한 뒤에 게임성 검증을 시작하지 않는다
6. 엔진 고르는 데 시간을 쓰지 않는다 (**결정 완료: 웹 · TypeScript · Vite**)
7. 카드 효과와 레시피를 코드에 하드코딩하지 않는다

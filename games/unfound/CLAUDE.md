# UNFOUND — 세션 공통 지침

이 저장소에서 작업하는 모든 클로드 세션은 아래를 따른다.

## 이 프로젝트의 조건

- 개발자는 **1인, 비개발자 출신, 다른 본업이 있어 시간이 매우 부족하다.**
- 역할 분담: 사람은 **기획과 결정**만 한다. 구현·검증·정리는 에이전트가 한다.
- 따라서 **대표에게 올리는 결정 요청은 한 번에 3개를 넘기지 않는다.** 넘길 것 같으면 기본값으로 처리하고 그렇게 했다고 한 줄 적는다.
- 아트는 약점이다. **아트가 없어도 검증이 진행되도록** 항상 설계한다.

## 무엇이 진실인가

1. `docs/00-SSOT.md` — 규칙의 유일한 기준. 다른 문서와 충돌하면 이 파일이 이긴다
2. `data/*.json` — 콘텐츠와 밸런스의 유일한 기준
3. 나머지 문서는 참고 자료다

규칙을 바꾸면 SSOT를, 수치를 바꾸면 `rules.json`의 changelog를 **반드시** 갱신한다. 이 프로젝트가 실패하는 가장 현실적인 경로는 코딩 실패가 아니라 **문서가 서로 어긋나서 무엇이 맞는지 아무도 모르게 되는 것**이다.

## 작업 전 항상

```bash
node tools/validate.mjs      # 데이터가 깨져 있으면 여기서 멈춘다
node tools/simulate.mjs 2000 42
```

## 에이전트 분담

| 에이전트 | 담당 | 넘기지 말 것 |
|---|---|---|
| `recipe-designer` | 카드·레시피 설계 | 코드 구현, 수치 튜닝 |
| `balance-analyst` | 시뮬레이션, 수치 튜닝 | 콘텐츠 생성 |
| `builder` | 게임 코드 구현 | 밸런스 결정 |
| `playtest-analyst` | 실제 플레이 로그 분석 | 시뮬레이션 분석 |

## 금지

- 카드·레시피·수치를 코드에 하드코딩
- `effects.json`에 없는 효과를 카드가 참조
- 미확정 규칙(`rules.json`의 `undecided`)을 임의로 확정
- 스타일 확정 전에 아트 에셋 제작
- 검증을 돌리지 않고 "좋아 보인다"로 종료

## 보고 말투

존댓말, 담백하게. 이모지 없음. 검증 과정과 설계 고민은 채팅에 쓰지 않고 커밋 메시지나 문서에 쓴다.
채팅에 쓰는 것은 **"지금 무엇이 되었는가"와 "대표가 무엇을 정해야 하는가"** 두 가지뿐이다.

# 게이트별 통과·킬 기준

기준은 숫자로 적는다. 숫자가 없으면 킬 판정이 매번 기분에 좌우되고,
"아까워서 계속"이 공정을 무너뜨린다. 기준 수정은 가능하지만 **판정 중에는 못 바꾼다** —
판정 전에 바꾸고 이유를 기록한다.

---

## G1 — 기획 (반나절)

산출물: 한 장 기획서(핵심 감정 / 핵심 루프 / 차별점 / 수익 가설 / 1인 제작 적합성).

즉시 킬:
- 핵심 감정이 **한 문장**으로 안 나온다
- 재미의 원천이 아트 물량이다 (1인·에셋 약점과 정면충돌)
- 유사작 대비 차별점을 한 줄로 못 쓴다
- 콘텐츠 제작량 추정이 1인 범위를 넘는다 (기준: 고품질 아트 필요 오브젝트 30개 초과)

통과 = 위 넷 모두 회피. 통과해도 "재밌다"는 아직 모른다. G1은 **거짓말 검사**일 뿐이다.

## G2 — 데이터 모델 + 시뮬레이션 (며칠)

산출물: `data/*.json` 스키마, 검증기, 시뮬레이터(2000판, 시드 고정), 기준선 지표.

통과 기준 (핵심 루프가 성립하는가):
- 턴/분당 **유의미 행동** ≥ 1.0 (게임의 핵심 동사가 실제로 자주 일어나는가)
- 핵심 자원 압박이 작동 (예: 점유율 ≥ 70%)
- 미사용 콘텐츠 비율 < 30%
- 승률이 검증 가능 구간 (20~90%)

킬/보류 기준: 지표 미달 상태에서 **개선 시도 3회**(값·콘텐츠 조정 라운드)로도 방향이 안 잡히면 보류, 원인이 기획의 구조 자체면 킬.

주의: 시뮬 AI는 사람보다 약하다. 절대값이 아니라 변화 방향으로 판단한다.

## G3 — 텍스트 수직 슬라이스 (몇 주)

산출물: 아트 없는(텍스트 카드/도형) 플레이 가능 웹 빌드 + 로그 수집 + 사람 플레이 지표.

통과 기준 (표본 10명 이상):
- 자발적 2판 이상 플레이 ≥ 50% ("한 판 더"는 말이 아니라 행동으로 센다)
- 첫 핵심 행동까지 ≤ 60초 (설명 없이 핵심 동사에 도달하는가)
- 평균 세션 ≥ 15분
- 종료 설문 "돈 내고 살 의향" ≥ 30%

킬/보류: 개선 2라운드 후에도 2판 이상 비율 < 30%면 킬.

## G4 — 콘텐츠 + 아트 + 출시

G3를 통과한 게임만 진입. 여기서부터 돈을 쓴다. 상세 공정은 통과작이 나오면 작성한다
(미리 만들면 돌릴 대상 없는 죽은 문서가 된다).

---

## 킬 절차

1. `games/<id>/STATUS.md`를 `KILLED`로 바꾸고 사유(어느 게이트, 어느 기준)를 적는다
2. `games/<id>/docs/90-postmortem.md` 한 장: 가설 / 어디서 죽었나 / 다음 게임에 가져갈 것 셋
3. 폴더는 지우지 않는다. 죽은 게임의 데이터·도구는 다음 게임의 부품이다
4. 공정 자체의 결함이 보였으면 `docs/pipeline.md`를 고친다 — 이것이 진짜 산출물이다

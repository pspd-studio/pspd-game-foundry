# 빌드 담당

너는 `data/`의 JSON을 읽어서 실제로 돌아가는 게임을 만든다.

## 절대 규칙

**카드, 레시피, 적, 지역, 밸런스 수치를 코드에 하드코딩하지 않는다.**
전부 `data/*.json`에서 런타임에 읽는다. 이걸 어기면 대표가 밸런스를 못 만지게 되고, 이 프로젝트의 파이프라인 전체가 무너진다. 예외 없다.

새 카드가 추가됐을 때 코드를 한 줄도 안 고쳐도 게임에 나와야 한다. 그게 통과 기준이다.

## 스택

- TypeScript + Vite. 프레임워크는 최소한으로
- 렌더링은 DOM/CSS 우선. Canvas는 필요할 때만
- 상태 관리 라이브러리를 도입하지 않는다. 이 게임의 상태는 순수 함수로 충분하다
- 전투 로직은 **UI와 분리된 순수 함수**로 짠다. `tools/simulate.mjs`가 같은 로직을 쓸 수 있어야 한다
- 배포는 Vercel. 커밋하면 플레이 링크가 갱신되는 상태를 유지한다

## 구현 순서 (이 순서를 지킨다)

1. 전투 코어 (순수 함수, UI 없음) + 테스트
2. 필드 7칸 + 카드 드래그 조합
3. 조합 즉시 효과 발동 + 적 하강
4. 공급 3장 선택
5. 발견 연출 (`discovery_text` 출력)
6. 도감 (발견한 레시피 목록)
7. 플레이 로그 전송 (Supabase)

1번이 끝나기 전에 2번을 시작하지 않는다. 화면부터 만들면 로직을 두 번 짜게 된다.

## 플레이 로그

플레이테스트 데이터가 이 프로젝트의 유일한 객관적 근거다. 아래를 익명으로 기록한다.

- 시도했으나 실패한 조합 쌍 (플레이어가 무엇을 기대했는지가 드러난다)
- 성공한 조합과 그 시점의 턴
- 턴별 필드 점유율
- 패배 시점의 턴과 적 종류
- 한 판 소요 시간

개인정보는 수집하지 않는다. 세션 식별자는 랜덤 생성값을 쓴다.

## 하지 말 것

- 아트 에셋을 기다리기. 카드는 **이름 텍스트 + 색 사각형**으로 먼저 굴린다. 스타일이 확정되기 전 아트는 전부 버려진다
- 기획에 없는 시스템을 임의로 추가하기. 필요하다고 판단되면 결정 요청으로 올린다
- 미확정 규칙(`data/rules.json`의 `undecided`)을 코드에서 임의로 확정하기. 스위치로 만들어두고 결정 요청으로 올린다
